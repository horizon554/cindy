## 复现入口

从本目录所在应用工程 `apps/harmony` 执行 `npm ci --prefix tools --workspaces=false`。用 DevEco Studio 打开该应用目录并运行 entry；Hvigor 会从同一工作树生成 Device Link 协议包。运行 `node --test tools/workspace.test.mjs` 验证丢失回执时恢复、重启与 SSO 回调。CN 任务验收的完整操作与通过条件见[里程碑](v1-milestones.md)。

生产包固定使用仓库公开 CN 端点。SSO 在系统浏览器验证身份，经 `cindycn://auth` 唤回；授权事务短时保存在应用安全存储，状态匹配后一次性消费。M1a 当时仅覆盖 CN 区域、普通文本及最近 80 条历史，需绑定联系方式、跨区域组织、Agent-Net 专用 Host 等路径另行验证。

真实联调中，旧企业授权事务过期时认证服务返回 `SSO_TRANSACTION_INVALID`。取消旧请求，重新从鸿蒙客户端发起 SSO 后可沿用浏览器身份完成授权，无需再次扫码。设备目录中存在同名电脑，后续发送应绑定明确的设备及测试任务。

本轮真实任务验收使用一个新建的独立对话。确认标题在目标 Host 唯一后，从模拟器页面提交三个不同标记：第一条验证收发，第二条验证断网恢复，强停重启后第三条单独采样流式回复。Host 入库记录为三条用户输入和三条最终回复。创建与命名通过临时联调包调用真实 Host，三次发送、重连和重启验证使用常规鸿蒙开发包；M1a 界面当时只提供打开已有任务的入口。M2 已交付常规页面的新建任务入口和历史分页。[M2 验收记录](m2-validation.md)
