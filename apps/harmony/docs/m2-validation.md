# M2 鸿蒙任务闭环验收

2026-11-26，M2.1 至 M2.3 已在鸿蒙工作树实现。DevEco 构建通过，手机模拟器已用真实 CN 账号连接 MacBook 上的 Cindy Desktop。M1b 签名真机复验仍待完成，M2 的整体验收保留这一项。

## 三个批次

| 批次 | 现在可以怎样使用 | 实现边界 |
| --- | --- | --- |
| M2.1 任务 | 选择电脑，分批查看任务，点「新建任务」填写可选标题，在详情中发送第一条消息；也可以继续已有任务。标题上方显示执行电脑，同名电脑附短标识。 | 新建普通对话读取所选 Host 的引擎和已保存的默认模型、来源、权限和推理设置。没有默认模型时会提示在电脑选择。创建意图先保存任务 ID，恢复时按同一 ID 查询结果。旧 Host 的远程列表接口按数量返回，每次展开 40 条，最多 1,000 条。 |
| M2.2 运行与交互 | 查看增量回复和工具状态，停止当前执行，继续暂停的队列；对审批选择本次允许或拒绝，回答单选、多选、自由输入或多道问题。 | 打开或恢复任务时读取 Host 的运行与待处理快照。提交前核对请求仍有效，决定使用原请求 ID。过期、其他端已处理和丢回执都有核对入口或反馈。特殊桌面交互会提示去电脑处理。 |
| M2.3 连续使用 | 查看更早的消息，断网或杀进程后重读已缓存内容和未发草稿；重连补齐历史，继续在原任务中工作。 | ArkData 加密关系库按 CN 账号、电脑、任务隔离目录、草稿、消息窗口和待核对的输入。每页通常 40 条，超过传输大小时缩页，每个任务保存最近已加载的最多 240 条。页首 Host 消息 ID 是继续向前翻页的游标。已知撤权会移除对应电脑缓存，退出会清除该账号缓存。设备完全离线期间，新的撤权决定要等通信恢复才能收到。 |

输入先持久化客户端消息 ID，再交给 Host。回执丢失后，应用通过 Host 的投递记录、队列或已落盘消息核对；重连本身不会提交输入。支持可靠投递的 Host 允许用原 ID 重试明确未收到的输入。旧 Host 缺乏足够证据时，应用保留待核对状态。后续编辑的草稿独立保留。

## 实际验收

| 环境 | 操作 | 观察结果 |
| --- | --- | --- |
| 手机模拟器 + 真实 CN Desktop | 从正式页面创建独立 M2 任务，发送文本并完成两次原生问答 | Desktop 只读查询确认测试标题唯一。模拟器选择的 Beta、Blue 分别成为 Host 端答案和最终回复，重开任务可读取。M1a 测试任务保留。 |
| 同一真实任务 | 第二轮请求较长输出，在执行中点击停止；另一次要求 Host 运行只读的日期命令 | 停止后按钮消失，随后同一任务仍可继续。日期命令执行时看见工具完成状态，最终回复回到鸿蒙任务详情，并能在重开后读到。 |
| 正常开发包 + 模拟器飞行模式 | 写入中文草稿，确认系统报告网络不可达，强停并重启；离线进入原电脑、原任务，再恢复网络 | 离线保留已收回复和草稿，发送禁用。恢复网络后原任务重新可发送。 |
| 同一套页面与控制器 + 独立模拟器测试包 | 使用可控的 Host 应答，在界面允许、拒绝、提交刚刚失效的审批，并多选两个答案 | 两种决定分别收到对应回执，失效请求移除并提示已过期或已在另一端处理；选中项有勾选标记，回传含两个选项。注入撤权后返回设备页，任务详情与操作入口消失。 |
| 独立模拟器测试包 + 系统键盘 | 在 93 条消息中向前分页，用拼音键盘逐字选择「你」「好」，系统返回后重新进入任务 | 前插一页后当时可见的 9 条消息位置逐条一致，继续滑动可到第 1 条。草稿恢复为「你好」，候选词未写进草稿。 |
| 正常开发包 + 模拟器系统设置 | 在系统设置切换深色、浅色，回到真实任务查看标题、历史和输入区 | 两种模式均实际显示，键盘打开时发送键完整可见。工程提供深色启动背景资源，系统控件随模式切换。[华为深浅色适配文档](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-guides/ui-dark-light-color-adaptation/) |
| 自动化回归 | 运行应用控制器和真实共享传输的丢回执场景，以及可控对端的创建重试、乱序返回、分页、过期决定和缓存隔离场景 | 创建回执丢失及连续点击只创建一次；已接收输入不会在恢复后重复发送；刷新保留顺序、清除已从 Host 历史移除的消息；旧账号或已撤权电脑的数据不能经任务页读回。 |

## 编辑最后一条用户消息

2026-11-28，在鸿蒙手机模拟器和本地集成测试中验收。

| 环境 | 操作与结果 |
| --- | --- |
| 模拟器连接真实 CN 电脑 | 打开唯一匹配的「M1a 验收测试」。空闲时只有最后一条可编辑用户消息显示铅笔按钮。点开后输入框显示原文，取消后恢复原草稿。真实会话的验收到取消为止。 |
| 模拟器运行态样例 | 在浅色和深色模式分别打开新旧两条用户消息的「更多」。只有最新消息的菜单里有「编辑」。点入和取消后任务都继续运行，原草稿恢复。 |
| 集成测试，模拟电脑回执 | 验证原附件回填、取消后恢复草稿和附件、连续点两次发送只重发一次。另一台控制端抢先追加消息时，电脑拒绝回退。回退成功但回执丢失后，重新打开任务可以取回编辑内容。 |

DevEco 的 `assembleHap` 构建通过，`node --test apps/harmony/tools/*.test.mjs` 共 7 项通过。含跨会话历史快照的消息暂不提供编辑入口，鸿蒙输入框尚不能重新读取这些引用的上下文。

## 构建与复测

工程位于 `apps/harmony`，基线为 `59d46dee61` 加鸿蒙工作树本地改动。常规 HAP 使用仓库的 CN 端点。上述独立测试包使用不同应用标识并替换对端响应，用于可重复地产生审批、过期、撤权和长历史。

- 在 `apps/harmony` 运行 `node --test tools/workspace.test.mjs`。使用 DevEco Studio 打开该目录，构建并运行 `entry@default`。
- 模拟器为 Mate 90 Pro、API 26。开发包为 `entry-default-unsigned.hap`，本次验收包 SHA-256 为 `a8e467ecfcc5f85063c88b7c5e8cc714c9062d3023cd9ef4a6853aba598429df`。
- 真机验收需用可安装的签名包，在正式华为手机上复测登录、切网、进程恢复、输入和滚动。后续 UI 批次已在真实 Desktop 验证允许、拒绝、逐设备撤权和恢复；真实双账号与真机仍待复测。[补充验收](ui-validation.md)
