# 鸿蒙手机 UI 验收

2026-11-26，CN，Mate 90 Pro 模拟器，API 26 / OpenHarmony-7.0.0.105。正式 Desktop 版本为 0.1.148，连接使用官方 Device Link。内测可继续；签名真机、两账号及发行通路见 [M4 发行准备](m4-readiness.md)。

## 与 iOS 和 Android 对照后的十项调整

2026-11-26，对照 apps/mobile 的 iOS、Android 共用页面、登录布局、启动资源和交互组件。模拟器运行原生 ArkUI。独立验收包使用测试账号、模拟电脑和测试文件。常规开发包保留原 CN 登录，访问真实桌面任务。

| 项目 | 当前交互 | 验证证据 |
| --- | --- | --- |
| 1. 启动与登录 | 冷启动使用品牌红与立绘。登录页按移动端同一组参数排列立绘、标语和字标，随屏高适配。深色使用对应素材。 | HAP 构建，模拟器浅色和深色登录截图。 |
| 2. 企业与手机号登录 | 企业 SSO 从独立入口进入组织页。手机号在请求验证码前确认条款，随后进入独立验证码页，倒计时结束后可重发。 | 模拟器未勾选时进入企业页。手机号测试认证端返回已发送后出现验证码页，倒计时按钮禁用。 |
| 3. 任务首页 | 按项目展示任务，可按名称、摘要或项目过滤已加载列表，可加载更多，支持全部、未归档和已归档。当前电脑返回一份运行摘要。多电脑且没有上次选择时，由用户选电脑。 | 模拟器进入首页。常规包按电脑和任务标题定位到真实任务。 |
| 4. 输入框 | 空闲时显示单行输入。聚焦后展开附件、语音和模型上下文，可拖动手柄调整高度，点击收起。 | 模拟器聚焦、选择附件、回到输入框，检查展开后的按钮。 |
| 5. 审批、问答与计划 | 审批与问答固定在底部，高风险操作分两次确认。风险内容变化须重新确认。必答未填禁用提交，计划可展开。 | 模拟器验证确认、拒绝、多选及展开计划。控制器测试覆盖两次点击之间待办被替换。 |
| 6. 新建与任务详情 | 新建时确认电脑和项目，输入首条消息后创建并发送。顶栏展示任务名和电脑，详情展示项目和引擎上下文。 | 模拟器选择目标并返回新建页。模拟丢失创建回执及重复提交，仅创建一个任务、发送一次首条消息。常规包打开真实任务详情。 |
| 7. 消息与历史 | 消息支持标题、列表、粗体、链接与代码块，工具记录可展开。到列表顶部继续向前滚动或通过菜单加载较早消息。 | 模拟器显示结构化测试消息。93 条测试历史从末尾进入早期消息，控制器验证去重和顺序。 |
| 8. 附件与系统分享 | 点附件预览、点叉移除。图片可单独查看，文件可交给系统打开。收到分享后可选择已有任务或新建，先进入草稿。 | 模拟器点开图片及文件预览，返回后附件仍在，点击移除才消失。控制器验证分享、上传迟到、预览授权和仅附件发送。 |
| 9. 运行与异常 | 使用轻量运行提示、停止与恢复入口。录音中显示时长，转写和取消跟随输入框。回执不明确时展示对应消息及核对或重试入口。 | 控制器验证停止、恢复、语音取消、迟到回调、断网草稿和原消息回执核对。 |
| 10. 设置与排版 | 账号与通知收进设置，任务页菜单打开当前任务详情。区分标题、正文和辅助信息的字号与深浅色。 | 模拟器进入账号与通知设置，检查深色消息与登录页。远端华为投递见 M4。 |

**待验与范围**　真实手机号收码、真机语音与读屏、华为远程通知投递仍需对应设备或服务。系统分享本轮复验到草稿的控制器链路，系统分享面板及本地通知曾在 [M3](m3-validation.md) 验收。普通受权 OSS 附件可取预览链接。仅保存在电脑上的路径及共享任务专用媒体会提示在电脑上打开。两端视觉基准取自移动端实现，本轮截图来自鸿蒙模拟器。

## 前一版三批操作记录

| 批次 | 用户操作 | 结果 |
| --- | --- | --- |
| 1 · 输入区与历史 | 在原生输入区发送文字或仅附件，执行中停止，通过系统拼音键盘逐字选词，回看历史 | 真实 Mac 收到空正文的单文件输入并返回预期回复；另一轮运行中停止成功。模拟器实际敲拼音时，候选“你”尚未确认，空草稿发送键保持禁用；选完“你好”后可发送，系统返回并重进仍是“你好”。 |
| 1 · 分页与断网 | 可控对端构造 93 条历史；另在常规开发包打开真实任务、开模拟器飞行模式、强停、冷启、恢复网络 | 修正了翻页后阅读位置跳动。实测补页前后 14 条可见消息的文字、屏幕坐标逐条一致，继续向前可读到第 1 条。断网时域名解析失败，冷启可读已收到的真实回复；输入测试草稿后发送仍禁用。恢复网络后草稿可发，Host 只读核实离线标记从未发送。验收后草稿恢复原有空值。 |
| 2 · 消息与审批 | 用户消息、助手文本、工具记录分别展示，审批与问答显示在待处理区；打开模拟器任务审批并在另一端检查结果 | 对两条独立的只读日期命令分别点“本次允许”和“拒绝”，真实 Mac 分别记录执行结果与拒绝，待办消失。另由两台独立身份的鸿蒙客户端打开同一条真实问答；第二端选 Amber 后，第一端自动收起问题并收到最终回复，Host 仅记录一条该轮用户输入。 |
| 2 · 过期与撤权 | 可控对端返回已失效决定、显示多选；真实 Mac 单独撤销和恢复一个验收控制端 | 失效请求移除并有提示。两个选项均暴露已选择状态，可提交。真实撤权后，独立验收客户端退出任务，电脑和旧任务入口消失；Mac 重新允许后，经刷新可重开同一任务，撤权前的未发送测试草稿已清空。 |
| 3 · 电脑、任务和登录 | 从电脑列表进入任务列表，打开与取消新建，重新进入已有任务；使用企业 SSO、退出并切换手机号登录 | 真实 CN 企业组织经系统浏览器授权，返回到独立验收包。退出后同意框清空、企业继续按钮禁用，切换到手机号入口时空号码的获取验证码按钮禁用。常规包中取消新建返回同一列表，原任务可继续打开。手机号收码及第二个真实账号的切换另列待验。 |
| 3 · 深浅色与触控 | 在模拟器系统“显示和亮度”中切换，回到同一任务查看标题、消息和输入区 | 浅色与深色均实际显示，草稿一致，输入和发送区清晰可辨；打开键盘仍可看到操作区。选项选择状态和图标按钮具有无障碍文本，真机读屏体验另验。 |

## 证据边界

- 常规开发包使用 CN 真实服务。测试前以只读方式确认指定 Mac 上的验收任务标题唯一；原有任务保留。真实撤权使用独立验收包和独立设备身份，只在 Desktop 该设备一行操作，并在验后恢复。
- 两条日期审批、空正文附件、停止、撤权和恢复在本轮前一开发构建及其独立验收包上完成，前一常规包 SHA-256 为 `118e977529de80bb3477cf090e2540ebbe8d525fbb3cca4c7b1861507c5ed0c3`。随后调整了分页入口及选项无障碍文案。
- 最终常规 HAP SHA-256 为 `15513aea69cd6add2221edc8ad1ae7671604cb2785e9a7211650055157e6b584`。已覆盖安装，沿用原 CN 登录，复验了真实任务、两端问答消失、飞行模式冷启动与联网恢复、列表返回。分页位置、过期、多选、系统拼音与深浅色通过同一最终页面源码的独立可控对端包验证。
- 运行 `node --test tools/*.test.mjs`，5 项集成测试通过，覆盖回执丢失、过期决定、分页、草稿隔离、附件与推送注册等路径。语音、系统分享与本地通知的原生能力验收沿用 [M3](m3-validation.md) 记录。开发包未签名，检查基线为 `59d46dee61` 加本地鸿蒙改动。
